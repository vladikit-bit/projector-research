> ### **R15-B — Buffer/output divergence proven, license relation unresolved**
> з частковим **R15-C**: candidate argument region з R14 (`DM 0x1BC8+`) **спростовано**

```
спільний decoder/state блок  DM 0x0FE0–0x10D0   → ОДНАКОВО активний в AC3 і DTS
                              ↓
вихідний/burst блок          DM 0x0900–0x0C00   → АКТИВНИЙ лише в AC3, у DTS повністю frozen
```

### Змінні слова між послідовними знімками

| регіон | AC3 | DTS |
|---|---|---|

## 4. Верифікація AC3-буфера (п.6)

| T (uptime) | `0x0A00` | `0x0A01` | `0x0A02` | `0x0A03` |
|---|---|---|---|---|
| 1238 | 000000 | 000000 | 000000 | **300000** |
| 1256 | 000000 | 000000 | 000000 | **300000** |
| 1275 | 000000 | 000000 | 000000 | 000000 |
| 1297 | 000000 | 000000 | 000100 | **300000** |
| 1321 | **f87200** | 6db600 | 000000 | 000000 |
| 1349 | **f87200** | b5ad00 | 000000 | 000000 |
| 1373 | **f87200** | 3c7800 | 000000 | 000000 |

Пошук по всіх знятих регіонах (upper16 ∈ {`0xf872`, `0x4e1f`}):

```
AC3: T=1321 → 0x0A00=0xf87200 ; T=1349 → 0x0A00=0xf87200 ; T=1373 → 0x0A00=0xf87200
DTS: жодного входження у всіх 7 знімках
```

**Підтверджено live:**
* **Pa = `0xF872` реально присутній у DM `0x0A00` під час AC3** — у трьох послідовних
  знімках, і **ніколи** під час DTS.
* **length = `0x3000`** спостерігається на `0x0A03` (`0x300000` = upper16 `0x3000`) —
  точно те значення, яке фігурувало в R11/R12.
* `0x0A01` змінюється від знімка до знімка (`6db600 → b5ad00 → 3c7800`) → буфер
  **перезаписується безперервно**; позиція preamble у 24-бітових словах плаває
  (кільцевий буфер / рухомий write-pointer).
* **Pb = `0x4E1F` живцем не спіймано**: при активному потоці він перезаписується між
  читаннями. R11 бачив його лише тоді, коли буфер був frozen (idle/DTS).

**Це прямо відповідає на п.5:** структура, яку будує static constructor
(`Pa/Pb/type/length`), **існує в runtime DM і збігається з DM `0x0A00`**. Зв'язок
static↔runtime встановлено на рівні вмісту (не на рівні «яка інструкція пише»).

## 5. Верифікація DTS (п.7)

```
DTS, усі 7 знімків:
  0x0900: 000000 000000 000000 982800     ← 0x0903 = 0x982800, НЕЗМІННИЙ весь час
  0x0A00: 000000 000000 000000 000000 000000 000000
  змін у 0x0900–0x0C00: 0
```

Порівняння динамічних регіонів:

| | AC3 | DTS |
|---|---|---|
| burst-регіон `0x0900–0x0C00` | **активний** (~220–320 слів/інтервал) | **0** |
| сталий залишок | змінюється | `0x0903 = 0x982800` закостявів |

**Результат:** відтворювана, абсолютна відсутність writer-активності в DTS.
Не «рідше», не «інше значення» — **жодного запису**.

## 6. Пошук чотирьох licensee-значень (п.4)

**Тemporal correlation з `dts m6 init ok` НЕ ОТРИМАНО** — DEC R2 log недоступний (§8).
Тому за вказівкою **жодне поле не називається licensee**.

Кандидати (останній знімок, AC3 / DTS):

| адреса | AC3 | DTS | коментар |
|---|---|---|---|
| 0x0FE8 | `000002` | `000000` | R11 теж; блок «гарячий» |
| 0x0FEB | `00006c` | `000000` | R11 теж |
| 0x10C7 | `0000c4` | `000000` | R11-кандидат |
| 0x10A6 | `7fffff` | `000000` | у R12 навпаки (DTS=7fffff) → **не latch** |
| 0x105B | `000001` | `000007` | R11-кандидат |
| 0x105E | `000001` | `000000` | R11-кандидат |
| 0x109B | `343574` | `664820` | у R12 DTS=`7fffff` → лічильник/рівень, **не latch** |
| 0x10C5 / 0x10CB / 0x10CD | `000000` | `000000` | у R11 AC3=`5` → **нестабільно між сесіями** |

### Тест на стабільність (найсильніший результат цього розділу)

Критерій: значення **константне в усіх 7 знімках AC3 і в усіх 7 знімках DTS**, але різне.

```
STABLE latches AC3≠DTS :  1
    0x0ff2    AC3=0x002432   DTS=0x004833
STABLE & EQUAL (спільні константи конфігурації) : 1081
```

`0x0FF2` — співвідношення ~1 : 2 (`0x2432` ≈ 9216+50, `0x4833` ≈ 18432+51) — це
**форматна константа розміру кадру** (AC3 1536 samples × 6 ch ≈ 9216; DTS ≈ 2×),
а **не ліцензійний прапор**.

> **Висновок:** у DM немає жодного стабільного «0 в DTS / 1 в AC3» прапора.
> Конфігурація обох кодеків практично ідентична (1081 спільних констант).
> Розбіжність — не у налаштуваннях, а у **факті виконання writer-а**.

## 7. PM read (п.10) — НЕ ВСТАНОВЛЕНО

```
read_dsp_sram_type=0 addr=0x100  → PM[0x100]=0x90f840, PM[0x101]=0x90f7b4, PM[0x102]=0x911135 …
read_dsp_sram_type=0 addr=0x0    → PM[0]=0x1805ef, PM[1..3]=0x0a001f, …
read_dsp_sram_type=0 addr=0x1000 → PM[0x1000]=0x90fd3a …
```

Команда працює і повертає 24-бітові слова, **але**:
* `0x90f840`, `0x90f7b4`, `0x911135` **відсутні як байти в усіх чотирьох образах**
  (`mst_codec_r2[_MS12V22]`, `mst_snd_r2[_MS12V22]`);
* наш образ у `0x100` містить `80 01 80 01 …` (boot stub), що не збігається з PM.

⇒ **Модель адресації PM не встановлена.** Можливо PM — це інший простір/банк, або
читання повертає перетворені дані. Потрібна окрема міні-розвідка; у цьому пасі не робив.

## 11. Підсумковий ланцюг

### AC3 (підтверджено runtime)
```
ES AC3 (offload)
 → DEC decoder/state блок 0x0FE0–0x10D0 активний (~40 слів/інтервал)      [R15]
 → IEC61937 preamble у DM 0x0A00: Pa=F872 live, length=0x3000 live        [R15]
 → регіон 0x0900–0x0C00 перезаписується безперервно (~220–320 слів/інт.)  [R15]
 → SPDIF TX → AVR locks DD                                                [R9]
```

### DTS (підтверджено runtime)
```
ES DTS (offload)
 → DEC decoder/state блок 0x0FE0–0x10D0 активний (~40 слів/інтервал)      [R15]  ← ДЕКОДЕР ПРАЦЮЄ
 → регіон 0x0900–0x0C00: 0 записів за ~130 с                              [R15]
 → DM 0x0A00 не містить F872 ні в одному знімку                           [R15]
 → тиша
```

### Чого бракує
```
license state (адреса невідома)
        ↓ ???
output decision / gate
        ↓ ???
IEC61937 constructor (static 0x045d4c/8a/ca; runtime-відповідник — запис у 0x0A00)
```
Обидві стрілки **не доведені**.

## 12. Чи виправданий мінімальний causal experiment?

**На даний момент — НІ, якщо це знову запис стану.**

Підстави:
* R11: запис у `0x10c5/0x10c7/0x10cb/0x10cd`, `0x105b`, `0x105e` — значення зберігаються,
  вихід не з'являється; «гарячий» блок `0x0FE8` перезаписується DSP <1 с.
* R15: стабільних latch-полів AC3≠DTS немає (лише форматна константа `0x0FF2`);
  1081 конфігураційних констант спільні.
* R15: регіон `0x1BC8+` не є живим станом → писати туди безглуздо.

**Що справді виправдано (і дешево):**
1. **Отримати licensee-адреси** — потрібен 16-бітний AEON-декодер для вікна
   `0x01e64a–0x01e686` (~60 байт). Це єдине, що закриває п.4.
2. **Знайти output-size/enable поле** в діапазоні, що активний в AC3 і не активний у DTS —
   тобто **всередині `0x0900–0x0C00` або безпосередньо перед ним** (а не в старому
   `0x0FE0–0x10D0`, який активний в обох).
3. **PM-модель** — без неї не звірити static-адреси конструктора з runtime.
4. Повторити R15 snapshots з `/tmp` (якщо вдасться його створити через remount) для
   temporal correlation з `dts m6 init ok`.
