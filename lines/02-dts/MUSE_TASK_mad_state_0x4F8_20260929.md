# Запит до Muse — фінальний шлях: MAD-стан у userspace-пам'яті

**Від:** Space Bunny
**Дата:** 2026-09-29
**Контекст:** F: повернувся, попередні знахідки перевірено. Нижче — головне, що лишилося.

---

## 1. Стан справи — коротко, щоб не витрачав час на повторний аудит

* DTS **декодується**: через Kodi з passthrough апаратний декодер іде `format : DTS, play state : PLAY`.
* **Хост-ліцензія DTS відкрита за замовчуванням.** `MDrv_AUDIO_Get_DTS_License` бере біт 7 з
  `0x112CF0`; `HAL_AUDIO_AbsReadReg` читає **16 біт** (`ldrh`); значення = `0xFF00` → біт 7 = 1 →
  `r6 = 0xF`. **І це дефолт, а не наш bitmap** — після ребута (bitmap зне) читається те саме.
  Отже наш IP-bitmap **ніколи не був вузьким місцем для DTS**.
* Єдиний блокер — **DSP-гейт** у DEC-фірмварі: `*(u16*)0xB000001E == 5`, або альтернатива
  `*(u8*)0xB000001D` (`&0x7F == 0` або знаковий `<= -1`). **Байт `0x80` задовольняє всі чотири
  гейти** без звернення до SE.
* Фірмвара цей регістр **тільки читає**. Пише SE.
* З userspace шляху до нього нема: `/dev/mem` відсутній, MAD-вузла нема, а
  `HAL_DEC_R2_Set_SHM_PARAM` має 0xD1 параметрів із зсувами **від 0x1014** — до `0x1C` не дістає
  (передекодовано 74, усі в смузі 0x1014…0x11C8).

## 2. Головна знахідка, яка відкриває шлях

`libapiAUDIO.so` (справжня, з `/mnt/vendor/tvservice/glibc/`, я її вже витягнув —
`/data/local/tmp` локально) має:

```
HAL_MAD_SpecifyDigitalOutputCodec  @0x8700C (512 B)
HAL_MAD_GetAudioCapability        @0x7E214
HAL_MAD_GetDTSInfo                @0x85C10 (580 B)
HAL_MAD_SetDTSCommonCtrl          @0x85AE8
HAL_AUDIO_GetDspMadBaseAddr       @0x5E154
g_DSPMadBaseBufferAdr             @0x8ABC00 (.bss)
```

Розбрав `HAL_MAD_SpecifyDigitalOutputCodec`:

```
0x87050  ldr r3,[r6] ; ldr r1,[r2,#0x4E8] ; eor ; lsr #16 ; cmp #0 ; beq +
0x8708c  mvn ip,#0                      ; інакше -1
0x870e0  bl  0x150A0
0x870f0  cmp r3,#5 ; cmpne r3,#2        ; <<< знову 5
0x87100  cmp r5,#1 ; cmp r5,#2
0x8711c  str r2,[r3,#0x4F8]             ; <<< ЗАПИС у MAD-стан
```

**`MAD_state + 0x4F8` — слово-кодек, що лежить у userspace-пам'яті `cpu_audio`**, через
звичайні GOT-відносні глобали. Тобто воно **читається і пишеться через `/proc/PID/mem`** —
на відміну від DSP-регістру, який лежить у kernel-просторі.

У живому `cpu_audio` (pid 499) `libapiAUDIO.so` має load bias `0xAFB85000`, тому
`g_DSPMadBaseBufferAdr` = `0xB0400C00`, і я прочитав його: перше слово `0xFE4780AD` —
**kernel-вказівник**, далі база лежить на `+0x90` від нього (недоступно).

## 3. Що саме потрібно від тебе

### Задача A (головна) — знайти MAD-стан у статиці `libapiAUDIO.so`

`HAL_MAD_SpecifyDigitalOutputCodec` дістає покажчики через `ldr r7,[r4,r2]` / `ldr r8,[r4,r3]`,
де `r4` — GOT-база, а `r2`/`r3` — зсуви в літеральному пулі. Розв'яжи їх у **статиці**,
щоб дістати:

1. имя/адресу глобалки, з якої береться MAD-стан;
2. **його фінальний зсув** (щоб у `cpu_audio` вирахувати runtime-адресу структури);
3. підтвердження, що структура — саме та, що містить `+0x4F8` і `+0x4E8`/`+0x4EC`.

### Задача B (допоміжна) — DTS-капібільна збірка

Якщо в тебе є firmware, де DTS **справді працює** (V098 / V474 / V083, або будь-який інший
TCL із підтвердженим DTS), розпакуй `libapiAUDIO.so` з нього і порівняй з нашим:

* чи є **`HAL_MAD_SpecifyDigitalOutputCodec`** там (у нас є);
* чи збігається **магічна перевірка** (`[r6] XOR [r2+0x4E8]`, старші 16 біт);
* чи є різниця в коді, який пише `+0x4F8`.

**Мета — не «полагодити», а знайти, чим наша збірка відрізняється від робочої.**

### Задача C (якщо впираємось)

Якщо вдасться дістати `libapiAUDIO.so` з **V083** (T615T01 ATV, старший за V098) — це
найстаріший доступний ATV-зріз, і найімовірніше найближчий до епохи, де DTS ще працював.

## 4. Формат відповіді

```
A. Глобалка MAD-стану:  ім'я / зсув / runtime-адреса в cpu_audio
   +0x4F8 читається як: ______ (16 біт)
B. Vxxx-зріз:  є SpecifyDigitalOutputCodec?  магічне значення: ______  різниці: ______
C. V083:  є / немає
D. Висновок: чи це той самий об'єкт, що бачить DSP-гейт
```

## 5. Чого робити **не** треба

* Не перевіряти знову IPAUTH/bitmap/SE-вікно/R2-mailbox — це закрито вимірами, звіти §18–§34.
* Не шукати `MApi_AUTH_Process` — його не викликається ніде, це підтверджено.
* Не аналізувати конфіг-розділи на ліцензію — перевірено, там порожньо.

## 6. Стан пристрою

Чистий. DTS не працює (як і до всіх експериментів), AC3/DD працює. Нічого не змінюється
без узгодження.
