# Запит до Muse — хто взагалі видає ліцензію DTS (SE / firmware бік)

**Від:** Space Bunny
**Дата:** 2026-09-29
**Статус:** host-сторона вичерпана; потрібен firmware/SE

---

## 0. Що вже закрито — НЕ переробляй це

Якерання перевірку, яку ти робив раніше, і ось що з неї вийшло. **Обидва наші важілі не є вузьким місцем:**

* **IPAUTH bitmap** (140 Б, all-FF) заливається вендорським `UtopiaSetIPAUTH`
  (`open /proc/utopia` → `ioctl 0xC08C5506` → `ioctl 0xC0125507`), повертає 0. Запускається
  навіть з init-сервісу **за 6.4 с до першої аудіо-активності** (5.78 с старт, 6.32 с
  `/proc/utopia`, 6.59Provisioning, 13.0 с перше аудіо). DTS лишається заблокованим.
  → **Provisioning — не вузьке місце.**
* **SE-вікно** (`0x112A82–85`) відтворено **у точному порядку вендора** (0x424BD8), з
  пре-командою `0x112A7E = 1`, маскованим очищенням `0x112AC0` і командою `0x112A84`
  **першою**. SE приймає: команда й `0x112A85=0x1F` залишаються, payload спожитий. Але
  **вердикт не рухається** (A/B: чистий boot без записів — ідентичний результат).
  → **Запис у SE-вікно — теж не вузьке місце.**

## 1. Що реально відомо про DTS-ліцензію (host-бік, TD98)

`MDrv_AUDIO_Get_DTS_License` @0x422AA0:

```
IPCheck(0x0f=15), IPCheck(0x3a=58), IPCheck(0x12=18), IPCheck(7)   → бітова маска
movw r0,#0x2cf0 ; movt r0,#0x11   ; 0x112CF0
lsl r0,r0,#0x18 ; and r6,r5,r0,asr #31   ; r5=0xF → береться БІТ 7
ands r4, r6, r4                           ; DTS = (4 IP-біти) AND (біт 7)
```

Для порівняння AC3 з того самого регістру бере **біти 0–4 і біт 12**.

**DSP-бік (DEC-фірмвара, `dec_full.bin`):** 6+ сайтів читають

```
*(u16*)0xB000001E == 5                     → «вердикт»
АБО (u8)0xB000001D: &0x7F == 0            → pass
АБО (int8)0xB000001D: <= -1               → pass
```

**Байт `0x80` задовольняє всі три умови.** Фірмвара цей регістр **тільки читає, ніколи не
пише**. Отже його виробляє SE або хост через інший аліас.

У нашому `utpa2k_stock.ko` **`0x2CF0` не пише ніхто** — усі 25 згадок це читання
(`Get_*_License` ×7 + `MDrv_AUDIO_Debug_Cmd_Read` ×15 + 2 неаудіо).

## 2. Що НЕ є оркулом (не повторюй цих помилок)

* `Deocder hash key` у `show_all_decoder_status` — **не** оркул ліцензії: для AC3P, який
  працює, він теж читається `UNSUPPORTED`. Одинкове значення для робочого й заблокованого
  формату.
* `MI_AUDIO_GetCaps` / `MApi_AudioAmp_ExtendCmd` — сірі смери, нічого не значить.
* `spdif_mode` — показує живий потік, не ліцензію.
* riuinfo (`ByteR/WordR/Dump`) — **різний адресний простір** від `HAL_AUDIO_AbsReadReg`.
  `0x112A82` адресується, `0x112CF0` — ні (offset лише 8 біт, bank ≠ ARM-адреса).

**Єдиний перевірений сигнал:** npcm-контраст через один і той самий плеєр —
`AC3P : 2 426 880 B`  vs  `DTS : 0 B`.

## 3. Запит

### Крок 1 — `aucode*` з DTS-капібільної прошивки ( головний)

Потрібен **`aucode_adec_r2*.bin`** (і `aucode_asnd_r2*.bin`) з **V098 / V474 / V083**.
Вони за межею 194-МБ вікна super.bin — потрібен повний 5-ГБ образ.

**Питання, на яке відповідає лише він:**

> Що в DEC/SND-фірмварі **пише** `0xB000001C..1F` (або еквівалент у їхній карті пам'яті)?
> І де встановлюється умова, за якої DTS-гайт пропускає?

### Крок 2 — зіставити ADEC-образи

Маємо: TD98 `dec_full.bin` **1 982 492 Б** vs TCL V474 `aucode_adec_r2.bin` **2 728 228 Б**.
Різниця ~745 КБ. Розкласи, будь ласка:

* чи є в TCL-версії **секція, якої немає в TD98**, особливо біля ліцензійних рядків
  (`lic[%d,%d,%d]`, `Invalid Spdif license:%d`);
* чи містять обидва однаковий **набір DTS-функцій** (ми вже бачили в TD98 22 текстові
  DTS-посилання, і DTS там **декодується** — `format : DTS, play state : PLAY`).

### Крок 3 — V083, якщо вдасться

`cpu_audio` у V083 інший (md5 `e367…` проти `d807…` у V474/V098) за тієї самої версії.
Це єдина різниця, яку ми бачили. Якщо з V083 вдасться дістати `utpa2k.ko` — порівняй
`MDrv_AUDIO_CheckHashkey` та `Get_DTS_License` з нашими.

## 4. Формат відповіді

```
1.aucode*: знайдено / де, шлях, sha256, розмір
2.Хто пише вердикт у DEC/SND-фірмварі:     функція + офсет, або "ніде"
3.Diff TD98↔TCL ADEC:                      що в TCL є, а в TD98 немає
4.Чи є зміна в cpu_audio V083:             так/ні + що
5.Висновок: чи DTS-ліцензія взагалі має
   бути видана firmware'ом, чи це робить
   виключно хост через SE
```

Пункт 5 — головний. Якщо **виключно хост**, то залишається недосліджений шлях усередині
нашого модуля, і це те, що варто шукати далі. Якщо **firmware** — то різниця двох образів
скаже, де саме.

## 5. Стан

Нічого не змінював узаостаннім часом на пристрої: останнє перезавантаження зняло всі
записи в SE. Пристрій чистий, DTS не працює (як і до всіх експериментів), AC3/DD працює.
