### 1.4 Перевірка гіпотези про `0x0F45` як стабільний бінарний diferenціал

Гіпотеза була: `AC3 ≠ 0`, `DTS = 0`, `IDLE = 0`.

**Результат: гіпотеза НЕ підтвердилася в частині IDLE.**

```
IDLE: [0x8] ×10   -> all zero = False   (n=10)
AC3 : [0x8] ×10   -> all nonzero = True (n=10)
DTS : [0x0] ×10   -> all zero = True    (n=10)
```

`0x0F45` — це **не** «прапорець, що вмикається лише під AC3». Реальний патерн:

```
0x0F45:  IDLE = 0x000008,  AC3 = 0x000008,  DTS = 0x000000
```

Тобто **DTS знешкоджує (скидає в нуль) поле, яке в стані спокою та під AC3 має значення `0x000008`**. AC3 його не встановлює — воно вже встановлене.

> Формулювання за правилом: `0x0F45` = **reproducible AC3-vs-DTS differential value** / **candidate control/state field**. Не «license flag», не «output flag».

### 1.5 Перевірка `0x0F4B` / `0x0F7B`

```
0x0F4B:  AC3 = 0xAA33C0 (10/10)   DTS = 0x2233C0 (10/10)   IDLE = 0x2233C0 (10/10)
```

**Підтверджено на всіх 10 незалежних семплах.** `0x0F7B` лежить поза вікном `0x0F40–0x0F50`; за попередніми двома прогонами — той самий патерн (`AC3=0xAA33C0`, `DTS=IDLE=0x2233C0`).

**Чи є поруч поле, що змінюється синхронно і краще пояснює різницю?** Перевірено сусідів `0x0F48`–`0x0F4E`:

- `0x0F4A`, `0x0F4C` — «живі» під AC3 (10 різних значень), нуль під DTS/IDLE. Вони **не синхронні** з `0x0F4B`: нестабільні, тоді як `0x0F4B` стабільний.
- `0x0F50` — рідкісні викиди (`0x78F100`, `0x9F3500`) лише під AC3; під DTS нуль. Теж не синхронний зі стабільним `0x0F4B`.
- `0x0F49` — одиничний викид `0x0001` під AC3.

**Висновок:** жодне сусіднє поле не змінюється синхронно з `0x0F4B`. Альтернативного пояснення різниці `0x0F4B` сусідами не знайдено.

### 1.6 Найсильніший якісний результат — «DTS ≈ IDLE» у цьому блоці

Порівняння колонок показує, що в діапазоні `0x0F40–0x0F50` **стан DTS майже ідентичний стану спокою**:

| addr | IDLE | DTS | збіг |
|---|---|---|---|
| 0x0F42 | 0 | 0 | ✓ |
| 0x0F45 | `0x000008` | `0x000000` | ✗ (DTS скинув) |
| 0x0F46 | 0 | 0 | ✓ |
| 0x0F47 | `0x0900` | `0x0900` | ✓ |
| 0x0F48 | `0x0900` | `0x0900` | ✓ |
| 0x0F49 | 0 | 0 | ✓ |
| 0x0F4A | 0 | 0 | ✓ |
| 0x0F4B | `0x2233C0` | `0x2233C0` | ✓ |
| 0x0F4C | 0 | 0 | ✓ |
| 0x0F4F | 0 | 0 | ✓ |
| 0x0F50 | 0 | 0 | ✓ |

Відмінності DTS від IDLE лише дві: `0x0F45` скинуто в нуль та `0x0F44 = 0x010000`.

**Ключове спостереження:** усі «живі» під AC3 поля (`0x0F46`, `0x0F47`, `0x0F48`, `0x0F4A`, `0x0F4C`, `0x0F50`) під DTS стоять на своїх **idle-значеннях**. Водночас лічильники `0x0F4D` (`0x01BE`) і `0x0F4E` (`0x01B6`) під DTS **вищі**, ніж під AC3 (`0x00CB`, `0x00C3`) — тобто DTS-шлях працював довше/активніше, а не «простоював».

Отже блок `0x0F40–0x0F50` під DTS **не оновлюється**, попри те що DTS-декодування йде (лічильники зростають).

> Формулювання: у цьому вікні DTS зберігає idle-конфігурацію; AC3 заповнює його робочими значеннями. Це **candidate control/state block**, а не доведена причина.

## Частина 2 — STATIC TRACE: спроба і чесний результат

### 2.1 Що було зроблено

1. **Локалізовано образи DSP:** `r2img/mst_snd_r2_MS12V22.bin` (1 839 920 B) — саме той SND-образ, для якого раніше (R8) було підтверджено відновлення бази SHM через `movhi/ori` (`r12 = 0x21a000`) і знайдено споживача `+0xfa`.
2. **Сканування displacement-полів:** пошук `0xF45 / 0xF4B / 0xF7B` як 16-розрядного displacement у слові, вирівняному на 4 байти, а також варіанти зі зсувом −2 (за аналогією з R8).
   - Знайдено: `0x0F45` — 12 збігів, `0x0F4B` — 20, `0x0F7B` — 8.
3. **Перевірка, чи це справді код:** підраховано розподіл опкодів по всьому образу. Код присутній (щільність верифікованого в R8 опкоду завантаження `l.hs` = 2–5% на блок, загалом 11 834 інструкції) — образ **не запакований**, сканування осмислене.
4. **Перевірка гіпотези «ARM-бік»:** пошук кодувань негайних значень `0x0F45/0x0F4B/0x0F7B` у 28 ARM-бінарниках (`libmi3*.so`, `audio.primary.mt5889.so`, `utpa2k*.ko`, `libutopia.so`, `libkodi.so` тощо). 32-розрядних літералів майже немає; кількість 16-розрядних збігів (~300 у `utpa2k.ko`) відповідає випадковому фону для бінарників такого розміру.
5. **Перевірка, чи значення є константами прошивки:** пошук `0x2233C0` / `0xAA33C0` як 32/24-розрядних констант в образах і бібліотеках — **значущих збігів немає**. Отже ці значення не є «зашитими» константами; вони обчислюються під час виконання.

### 2.2 Результат: **writer/reader НЕ встановлено**

**Жоден зі знайдених збігів не підтверджено як інструкцію, що звертається до `0x0F45` / `0x0F4B` / `0x0F7B`.** Причини:

1. **Не встановлено базу DM-вікна.** У R8 база SHM була доведена (`movhi/ori` → `0x21a000`), і displacement `+0xfa` давав перевірену ефективну адресу. Для `0x0F45` еквівалентної матеріалізації бази (`movhi/ori`, що дає вікно, всередині якого `0x0F45` є зміщенням) **не знайдено**. Без бази displacement не має сенсу: `0x0F45` могло б бути displacement, літералом, частиною таблиці або випадковим збігом.
2. **Контекст збігів не схожий на код доступу до структури.** Довкола збігів (наприклад `0x0246E8`, `0x052A50`) немає ні сталої бази регістра, ні серії сусідніх звернень до близьких зміщень — тобто немає ознак типового блоку читання/запису поля структури.
3. **Не визначено, чи адресується цей регіон узагалі як пам'ять.** Клітинки DM, доступні через інтерфейс дампів, не обов'язково є memory-mapped для DSP-коду. Можливо, немає жодної інструкції з адресою `0x0F45`, попри те що значення читається дампом.
4. **Brute-force заборонено.** Наказ вимагав працювати лише за ланцюгом `known SHM base → адреса → найближча load/store → control flow → caller`. Цей ланцюг для `0x0F45/0x0F4B/0x0F7B` **не замикається**: перша ланка (база) відсутня.

### 2.3 Статус за правилом Evidence

**VERIFIED (runtime)**

- У діапазоні `0x0F40–0x0F50` існує **5 стабільних AC3↔DTS diferenційних значень** (`0x0F44`, `0x0F45`, `0x0F4B`, `0x0F4D`, `0x0F4E`), кожне підтверджене 10/10 семплами.
- `0x0F4B`: `AC3 = 0xAA33C0`, `DTS = IDLE = 0x2233C0` — 10/10 у кожному стані.
- `0x0F45`: `AC3 = IDLE = 0x000008`, `DTS = 0x000000` — 10/10 у кожному стані. Гіпотеза «IDLE = 0» **спростована**.
- `0x0F7B` (два попередніх прогони): той самий патерн, що й `0x0F4B`.
- Жодне сусіднє поле не пояснює різницю `0x0F4B` синхронною зміною.
- Блок під DTS збігається з IDLE майже повністю (11 з 13 порівнюваних клітинок), попри зростання лічильників `0x0F4D/0x0F4E`.

**VERIFIED (static)**

- Образи DSP локалізовано; SND-образ містить дійсний, не запакований код.
- Значення `0x2233C0` / `0xAA33C0` **не є** константами прошивки (не знайдено як літерали) — вони обчислюються під час виконання.
- Для порівняння: раніше (R8) для SND SHM `+0xf8` writer/reader **було** встановлено через доведену базу `0x21a000`. Це показує, що метод працює там, де є база.

**STRONG INFERENCE**

- Блок `0x0F40–0x0F50` є **candidate control/state block**, який AC3-шлях заповнює робочими значеннями, а DTS-шлях залишає у стані спокою. Той факт, що лічильники `0x0F4D/0x0F4E` під DTS **вищі**, посилює інтерпретацію: DTS-обробка йде, але цей блок нею не оновлюється.

**UNRESOLVED**

- **Хто записує `0x0F45` / `0x0F4B` / `0x0F7B` — не встановлено.**
- **Хто читає ці клітинки — не встановлено.**
- **Control-flow наслідок — не встановлено.**
- Чи існує ланцюг `AC3/DTS identification → write 0x0F45/0x0F4B/0x0F7B → later read → SDO/IEC61937/DTS packer decision` — **невідомо**.
- Чи адресується цей регіон кодом DSP як пам'ять — **невідомо**.
- Причина відмови DTS **не встановлена** і не може бути виведена з diferenційності поля.

### 2.4 Що потрібно для завершення static trace

1. **Знайти базу DM-вікна** — `movhi/ori` (або еквівалент), що матеріалізує адресу, всередині якої `0x0F45` є displacement. Найперспективніше: пошук у SND-образі послідовностей, що формують малі значення типу `0x0F00` / `0x1000`, із подальшим пошуком load/store з displacement у діапазоні `0x40–0x80`.
2. **Підтвердити адресацію DM** (чи memory-mapped вона для DSP, чи доступна лише через сервісний інтерфейс дампів). Якщо не memory-mapped — шукати writer/reader треба не в DSP-коді, а в сервісному/діагностичному шляху.
3. **Визначити IA/encoding AEON** для достовірного дизасемблювання (без цього decoding спирається лише на один верифікований зразок інструкції).
