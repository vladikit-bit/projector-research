# R57 — НА ДРОТІ: прямий захват SPDIF TX non-PCM (AC3 vs DTS)

**Дата:** 2026-09-12 · **Режим:** read-only інструмент платформи (`dump_spdif_npcm`), нічого не патчено.
**Пристрій:** C50A / MT5889, стан: V1-patch SND (Pc 0x01→0x0B) ВСЕ ЩЕ ВСТАНОВЛЕНИЙ.

---

## 0. Головне

Знайдено **штатний механізм прямого захвату байтів, що йдуть у SPDIF TX** —
`echo dump_spdif_npcm=1 path=1 > /proc/utopia_mdb/audio` →
файл `/data/DUMP_audio_spdifNpcm_NN.bin`.

Це **спростовує попередній вердикт R25/R26** («Pc на дроті структурно неспостережуваний»).

---

## 1. Як виглядає РОБОЧИЙ AC-3 burst (контроль)

Файл `ac3_03.bin` (571392 B), початок:

```
72 f8 1f 4e  01 00  00 30  77 0b  67 ac 40 1c f8 eb ...
```

Розгортання (байт-свап, як його бачить SPDIF-периферія):

| місце | байти на дроті | значення | поле |
|---|---|---|---|
| 0..1 | `72 f8` | `0xF872` | **Pa** |
| 2..3 | `1f 4e` | `0x4E1F` | **Pb** |
| 4..5 | `01 00` | `0x0001` | **Pc = AC-3** ✓ коректно |
| 6..7 | `00 30` | `0x3000` | **Pd = 12288** = 1536 B × 8 |
| 8..9 | `77 0b` | `0x0B77` | AC-3 payload syncword |
| 10+ | … | | payload (змінюється) |

Примітка: кожна 16-бітна пара в дампі зберігається **байт-свапнутою**
(`F872` → `72 F8`). Це не помилка — так виглядає регістр передавача.

**AC3 = ВАЛІДНИЙ IEC61937 AC-3 burst, Pc правильний, payload живий (змінюється).**

---

## 2. Що йде на дріт під DTS

Файл `dts_01.bin` (270336 B), початок:

```
72 f8 1f 4e  01 00  00 30  77 0b  50 0f 40 1c f8 eb ...
```

| місце | DTS | AC3 (контроль) |
|---|---|---|
| Pa | `F872` | `F872` (однаково) |
| Pb | `4E1F` | `4E1F` (однаково) |
| **Pc** | **`0x0001`** | **`0x0001`** |
| **Pd** | **`0x3000`** | **`0x3000`** |
| **payload sync** | **`0x0B77`** ← AC-3! | **`0x0B77`** |
| payload | `500f…` (стале) | `67ac…` (живе) |

### 2.1 Блок НЕ оновлюється

Розмір блоку `0x1800`. Розподіл:
- DTS: **26 копій одного й того самого блоку**, потім ще 17 копій іншого — разом **лише 3 унікальні блоки** на 270336 B.
- AC3: **3 унікальні блоки на 93** — тобто майже кожен блок свій (реальний потік).

Блок, що транслюється під DTS, **не знайдено в AC3-дампі** (0 збігів) —
це не «останній AC3-кадр», а **стале заморожене вмістиме буфера**.

### 2.2 Різниця DTS↔AC3 лише в байтах payload

У перших 64 байтах різниця тільки за зсувами **10, 11, 36, 37, 38, 39** —
тобто **виключно всередині payload**. Заголовок (Pa/Pb/Pc/Pd) і payload-syncword
`0B77` **байт-у-байт ідентичні AC-3**.

---

## 3. Висновок

Під DTS у SPDIF TX **не потрапляє DTS burst**:

1. **Pc = `0x0001` (AC-3)** — не DTS (`0x0B/0x0C/0x0D` або MStar-варіант `0x111/0x211/0x311`).
2. **Pd = `0x3000`** — це AC-3-довжина, не DTS-довжина.
3. **payload-syncword = `0x0B77`** — AC-3 sync, не DTS `7FFE8001`.
4. **Вміст блоку сталий** → буфер **не перезаписується**; передавач **ретранслює залишок**.

**Отже корінь не в значенні поля — а в тому, що DEC-шлях IEC61937-writer-а
для DTS не виконується взагалі.** Тобто механізм: або (а) DTS не доходить до
DEC packer-а, або (б) packer виходить раніше / повертає помилку.

---

## 4. Де шукати далі (з новим приладом)

DEC містить **повний коректний DTS-механізм** — знайдено статично:

| адреса (DEC file offset) | що робить |
|---|---|
| `0x45D07` | IEC61937 data-type селектор: `r6=samples>>2`; 4096→`0x311`, 8192→`0x411`, 16384→`0x511`, default→`0x011` |
| `0x45D62` | продовження: 1024→`0x111`, 2048→`0x211`, default→`0x011` |
| `0x45D4C/8A/CA` | запис Pa/Pb у слоти `+0x16D/+0x16F`, data-type →`+0x171`, len→`+0x173` |
| `0x4618E` | виклик білдера з `r6=0x800` (2048) |
| `0x46259`/`0x46266` | **DTS syncword-райтер:** пише `0x7FFE8001` (core) |
| `0x462DE`/`0x462ED` | пише `0x1FFF E800` (**DTS-HD** sync) |
| `0x461F7` | `bg.bnei r24,0x54E,→0x462A0` — розгалуження |
| `0x64624` | **DTS syncword-ДЕТЕКТОР:** `80017FFE`, `FE7F0180`, `58642520`, `1FFFE800`, `00E8FF1F` |

Ключове: **DTS-механізм існує й виглядає коректним** — але він **не спрацьовує**.
Точка, яку треба довести: **яка умова не виконується**, щоб цей шлях пішов.

## 5. Артефакти

| шлях | вміст |
|---|---|
| `ac3_00.bin`, `ac3_03.bin` | SPDIF TX non-PCM під AC-3 (md5 `4f0bec56…`, `103147c9…`) |
| `dts_01.bin` | SPDIF TX non-PCM під DTS (md5 `2551c648…`) |
| цей файл | висновок |

**Прилад для повторення:**
```bash
adb shell "echo 'dump_spdif_npcm=1 path=1' > /proc/utopia_mdb/audio"   # старт
# ... запустити відтворення ...
adb shell "echo 'dump_spdif_npcm=0 path=1' > /proc/utopia_mdb/audio"   # стоп
adb pull /data/DUMP_audio_spdifNpcm_NN.bin
```
