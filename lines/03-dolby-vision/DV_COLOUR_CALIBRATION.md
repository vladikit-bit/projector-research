# Калібрування кольору Dolby Vision на TD98 Pro — стан і шлях

**Дата:** 2026-10-03. **Пристрій:** C50A, mt5889, `mt5889_k32-userdebug`.
**Статус:** вимірювальний шлях побудовано, сам дефект ще не виправлено.

## Коротко про проблему

Dolby Vision **декодується** коректно (конвеєр, метадані, тонапінг рухаються), але
картинка неправильна: літера «N» видається **оранжевою замість червоної**, і всю картинку
косить «молоко» — піднятий чорний.

Орієнтир, знятий 2026-10-03 при DV + Vivid:

| | виміряно | еталон Netflix `#E50914` | відхилення |
|---|---|---|---|
| N | `#903E02` R=145 G=62 B=2 | R=229 G=9 B=20 | — |
| G/R | **0.431** | 0.039 | зелений **×11 завищений** |
| B/R | **0.014** | 0.087 | синій **×6 притиснутий** |

Чорний: мінімум яскравості **17** (Bright) і **25** (Vivid) замість 0.

## Три незалежні джерела вимірювання

| джерело | що дає | шлях | обмеження |
|---|---|---|---|
| `screencap` | повний RGB, 1920×1080 | **до** світлового тракту | показує результат декодування, не те, що видно |
| камера (`/data/uvc_grab`) | лише яскравість | **після** світлового тракту | **монохромна** — кольору не бачить узагалі |
| око користувача | реальний видимий результат | — | суб'єктивно |

**Панель показує колір правильно.** Логотип NETFLIX у **SDR** дав `#F6000D` при
еталоні `#E50914` (збіг R=17, G=9, B=7). Отже дисплейний тракт справний, поломка
**вище** за нього, у декодуванні DV.

## ⭐ Вбудований інструмент: галерея суцільних кольорів

`Factory Menu (MediaTek) → Other Options → Test Pattern For Panel`
навігація `Prev / Next`, масштаб `UP / DOWN`.

| # | колір | значення |
|---|---|---|
| 1 | Червоний | `#FE0000` |
| 2 | Зелений | `#00FF01` |
| 3 | Синій | `#0000FE` |
| 4 | Жовтий | `#FFFF01` |
| 5 | Пурпуровий | `#FF00FF` |
| 6 | Бірюзовий | `#01FFFF` |
| 7 | Білий | `#FEFEFE` |
| 8–9 | Сірі | `#7D7D7D`, `#7C7C7C` |

Плюс окремий регулятор балансу:
`Design Menu → Test Pattern → XC WHITE BALANCE mode` →
`XC_WHITE_BALANCE enable` (0…1) + `White Balance Radio` (0…100).

⚠️ У діалозі `ENTER` дописує цифру, а `BACK` стирає все введене.

## Відхилені гіпотези — перевірено числами, не припущеннями

| гіпотеза | перевірка | результат |
|---|---|---|
| DV `Compression` Line/RF | літера N замірах режимів | **різниця 0.0** — не причина |
| DV-профілі Vivid/Dark/Bright | усі поля нейтральні | не причина |
| W/B Adjust (Picture Mode, Color Temp) | таблиця зібрана, DV вище за цей рівень | не причина |
| ADC Adjust | R/G/B однакові 1509 | не причина |
| **камера «монохромна»** | Y=16…235, U=V=128 **точно**, на всіх 4 конфігураціях | **причина не в камері для нашої задачі**; камера придатна для яскравості |

## Живі кандидати — записані в конфігурації, не гіпотези

| кандидат | значення | механізм |
|---|---|---|
| **Brightness-крива** | вхід **0% → 88** | низ піднято прямо в таблиці `Non_linear` |
| **BackLight-крива** | вхід 0% → **8192** | підсвічування не гаситься |
| **DBC** (`PQConfig.ini`) | `g_DBC_Y/C_GAIN` = 0x48/0x50 при дефолті 0x40 | піднімає рівень цілого зображення |
| **Global Dimming** | **开 (увімкнено)** | має затемнювати чорний, а піднімає |
| **PQ-калібрування DV** | 11 полів = **0.0** | рушій: `Customer IP is not set as customer mode` |

## Шлях provisioning'у — `Factory PQ Update`

`Design Menu → Other Options → Factory PQ Update`

```
PQ Update Type   Bin | Ini | All
PQ Update        Please Click!     <- НЕ натискати без згоди
```

Тип **`Ini`** означає, що рушій уміє брати калібрування з INI-файлу. Дані на місці:

```
/vendor/tvconfig/config/HDR_BIN/dolby_factory.cfg
    Tmax=281  Tmin=0.23  TEOTF=POWER  Tgamma=2.2
    TPrimaries=0.6291 0.3425 0.3100 0.6106 0.1508 0.0496 0.3124 0.3319
/vendor/tvconfig/config/HDR_BIN/dolby.bin      14235 Б — НЕ заглушка, 256 різних значень
/vendor/cusdata/bsp/chip/aq/Dap/dolby_dap_tuning_config.dat   520 Б, бінарна таблиця
```

**Це конфігураційний шлях, а не патч.**

## Що не зроблено

* 11 полів PQ-калібрування **не заповнено** — `Factory PQ Update` не натискали.
* `Global Dimming` **не перемикався** — перший і найдешевший тест, одне натискання.
* Вимірювання через галерею кольорів **почате, але не завершене** — перші три значення
  камери (141 / 213.5 / 182) отримані, зона `screencap` була хибною і потребує
  перевимірювання.
* `panel_gamma.bin` (8256 Б) **не розібраний**.
* `Advanced Effect → DAP Setting` — 15 груп аудіо-DSP, увімкнення OFF, не досліджено.

## Відкат

Усі зміни в інженерних меню повернуто в нейтраль. `dv3`-патч (`/vendor/lib/modules/utpa2k.ko`,
md5 `d28b1080…`) лишається встановленим; stock — `/data/utpa2k_STOCK_BACKUP.ko`
(md5 `2fc6e9fc…`), відкат = `cp` + перезавантаження.

## Корисні дрібниці

* `adb root` **втрачається** після кожного перезавантаження — `screencap` у `/data`
  починає давати `Permission denied`. Працювати через `/sdcard` або повторно `adb root`.
* Режими **не обертаються** — зупиняються на краях, для повернення потрібен `LEFT`.
* У **W/B Adjust** `DOWN` не рухає рядки; рухає лише `Source`.
* `uiautomator` **не віддає** `focused`/`selected` — підсвічування видно лише на екрані.

# ⭐ РОЗВ'ЯЗОК 2026-10-03: шлях до відсутніх PQ-файлів і файл кривих

Це дописує суттєве — попередній документ писав «де шукати далі», тепер шлях названий.

## 1. Панель описана — у власному INI

`/vendor/cusdata/bsp/common/panel/UD_VB1_8LANE_CSOT_URSA_PWM_INVERSE.ini` (37 КБ)

```ini
[panel]
m_pPanelName       = UD_VB1_8LANE
m_ePanelLinkType   = 10        # LINK_LVDS

[CUSTOMER_PQ]
Main_pq_path = "/vendor/tvconfig/config/CUSTOMER_PQ_BIN/Main_Color.bin";
Sub_pq_path  = "/vendor/tvconfig/config/CUSTOMER_PQ_BIN/Sub_Color.bin";
```

**Каталогу `/vendor/tvconfig/config/CUSTOMER_PQ_BIN/` НЕМАЄ** (перевірено).

Тому ланцюг PQ **доведений, а не припущений**: панельний INI називає точний шлях →
каталогу немає → рушій пише `Customer IP is not set as customer mode` і
`PQ_BIN_NOT_ENABLE` → тон-мапінг не застосовується. `dolby_factory.cfg` містить
**значення**, але ніхто не завантажує їх у ці файли.

`Panel Info` порожня не суперечить: за вихідним кодом панель читається з **EEPROM**
(`getPanelType` / `readFromEeprom`), а EEPROM порожня, хоча INI-опис на місці.

## 2. Підсвічування не може погаснути — фізична підлога чорного

```ini
m_ucMaxPWMVal  = 0xFF
m_ucMinPWMVal  = 0x20
u16MaxPWMvalue = 0xFFFF
u16MinPWMvalue = 0x2000      <- 12.5% від максимуму
```

Джерело світла не опускається нижче 12.5%. **Це саме по собі гарантує піднятий чорний**
і збігається з виміром: мінімум 17 (Bright) / 25 (Vivid) замість 0.

## 3. ⭐ NLA.ini — файл за значеннями в меню, і він редагується

`/vendor/tvconfig/config/PQ_general/NLA.ini` (2294 Б), **однакові дані для всіх
дев'яти джерел** (CVBS, SVIDEO, YPbPr, VGA, SCART, HDMI, DTV, ATV, Others):

```
0,25,50,75,100,          точки OSD
88,108,128,138,148,      BRIGHTNESS   <- 88 на вході 0
30,64,125,192,255,       CONTRAST     <-  30 на вході 0
0,87,178,222,255,        SATURATION
0,11,23,41,63,           SHARPNESS
0,25,50,75,100,          HUE
8192,22528,36864,50944,65280   BACKLIGHT  <- 8192 на вході 0
```

**Це байт-у-байт ті значення, які я виміряв у меню.** Одна правка діє на всі джерела.

Це і є важіль калібрування у редагованому вигляді: три з цих шести значень на вході 0 —
це **підлоги, а не нейтраль**.

## 4. Заводські криві по 101 точці — увімкнені

Той самий INI, секція `[picture_mode]`:

```ini
bPictureModeUseFacCurveFlag = 1     # use Factory non-linear Curve
contrast_curve[101]  = { 0x10, ... }
brightness_curve[101] = { 0x74, ... }   # 0x74 = 116 на вході 0
```

Секції: `[panel] [CFD] [ursa] [CUSTOMER_PQ] [gamma_table_x] [gamma_table_0..3]
[picture_mode]`. З `[ursa]`: панель **10-бітна** (`m_PanelBitNums = 2`).

## 5. Вихідний код меню знайдено

`github.com/ljqiing/xinfuyijia` — наше меню, 9 років тому. Звірено з пристроєм.

* `MS_NLA_SET_INDEX {volume, brightness, contrast, saturation, sharpness, hue,
  backlight}` — рівно сім кривих, які я виміряв.
* `MS_NLA_OSD_POINT {0,25,50,75,100%}` — рівно п'ять точок.
* **Колірна температура:** `factoryColorTmpEx.astColorTempEx[colorid][source]` з
  `.redgain/.greengain/.bluegain` + три offset. **Кожна температура × кожне джерело має
  власні значення** — ось чому вони різнилися.
* Застосування — один виклик:
  `fm.setWbGainOffsetEx(enColorTemp, rgain, ggain, bgain, roff, goff, boff, src)`.
* Індекси шукаються **за джерелом**: `queryePicMode(curInputSrc)` потім
  `queryColorTmpIdx(curInputSrc, idxP)`.
* `EN_MS_COLOR_TEMP {cool, nature, warm, user, user2}` — наш `Standard` це **`nature`**,
  і є **`user2`**, якого в нашому меню немає (4 значення, а не 5).
* `EN_MS_PICTURE` — 10 SDR-режимів, у нас видно 6.
* Провайдер `mstar.tv.factory`, колонки `u16RedGain`… і `u8OSD_V0/V25/V50/V75/V100`.

**Наш провайдер — `com.ntech.factory.provider`**
(`com.bk.factory/.provider.FactoryProvider`). Він **відповідає, але всі таблиці
повертають `No result found`** — фабрична база ніколи не заповнювалася.

## Що це дає для калібрування

Три редаговані підлоги, які тримають чорний піднятим:

| де | значення на вході 0 | файл |
|---|---|---|
| Brightness-крива NLA | 88 | `PQ_general/NLA.ini` |
| Contrast-крива NLA | 30 | `PQ_general/NLA.ini` |
| Заводська brightness-крива | 116 (0x74) | `panel/UD_VB1_…PWM_INVERSE.ini` |
| Мінімум PWM | 12.5% | там само |

Це **текстові файли**, у нашій власній прошивці, з прямими шляхами.

## Порядок калібрування (пропонований)

1. Вимкнути DV, грати SDR — еталонний стан
2. Показати галерею суцільних кольорів, зміряти `screencap` **і** камерою
3. Крутити `NLA.ini`: Brightness[0] 88→0, Contrast[0] 30→0
4. Після кожної зміни — перезавантаження й повторний замір галереї
5. Перевірити на DV
6. За потреби — `PWM_INVERSE.ini` (підлога PWM, `brightness_curve[0]`)

**Обережно:** зміна `NLA.ini` змінює передавальну функцію панелі для ВСІХ джерел, тому
кожен крок потребує заміру, а не «на око».
